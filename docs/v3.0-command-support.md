# v3.0 命令资料范围与检查能力

选择厂商表示使用对应厂商的独立解析器和规则。命令补全资料、源文本规范化、参数及关联检查、设备运行验证是四种不同能力。软件没有声称覆盖厂商全部产品、型号、软件版本、板卡和许可；命令条数和零诊断都不能作为设备配置正确的证明。

## 每行结果如何理解

`coverage.pending_lines` 和 `coverage.pending_line_details` 保留所有未校验行号及原因：`catalogued` 为仅识别命令族、`unparsed` 为未解析、`unsupported` 为未实现对应语义、`context_required` 为缺少所属视图。待校验清单不复制配置正文，避免摘要历史或只导出诊断时带出敏感参数。

`recognized` 仅表示已进入软件的规范化模型。`semantic_complete` 为假时必须查看待校验内容；为真也仅表示本次输入没有已登记的解析缺口，不保证设备语法、型号适用性、链路运行状态或所有潜在问题都已被验证。配置片段中的对象缺失继续保留 Unknown。

## 本次新增的可检查事实

H3C `port access vlan`、`stp global enable/disable`、`acl basic` 和带逗号的 Comware 7 `version …, Release …` 提供具有区分度的自动检测依据。只有 `sysname`、普通接口或 `stp mode mstp` 等共享语法时继续要求用户选择厂商。混合厂商的独特命令或版本横幅不能按最高置信度强行归类。

两套解析器统一处理行首终端提示符和纯 `# 说明` 注释。原文、命令参数、引号内容和源行号保持不变；`#` 单独一行仍是配置视图分隔符。已显式给出的接口/BGP/OSPF视图可以与后续终端视图提示符关联，未知提示符视图不被猜成配置事实。

H3C 聚合接口支持 `link-aggregation mode dynamic` 和 `undo link-aggregation mode`；Huawei Eth-Trunk 支持 `mode lacp-static`、`mode manual load-balance` 和 `undo mode`。切换和撤销后只保留最后有效模式及源行。默认模式按下列资料分别记录为 `static` 与 `manual load-balance`，其 `aggregation_mode_origin=reference_default` 表示来源文档中的默认值，仍需核对实际型号版本。H3C 的显式 `static` 等其他型号版本新增形式以及其他未实现模式/参数不因共享首词被自动规范化。

模式命令仅在对应聚合接口视图中规范化。成员引用仍由各厂商已有规则检查；本机 LACP 模式和成员配置只能说明本地意图，新增 H3C-IF-007/HUA-IF-007 明确显示 Unknown，要求比对对端和当前协商、成员状态。

Huawei 的 10GE、25GE、40GE、100GE 分隔及合并接口写法使用同一身份，配置、路由接口引用、接口运行表及 LLDP 记录共用规范化。每种数字开头类型分别来自已纳入的官方资料见下表，不把该集合外推到所有设备。未知类型、尾部视图限定和其他视图里的纯数字参数仍保留待校验。
