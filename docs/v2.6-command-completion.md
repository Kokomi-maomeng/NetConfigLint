# v2.6 指令补全与厂商数据检查

## 操作

厂商选择旁的“指令补全”控制补全范围，与配置检查的厂商选择独立。初始选择自动识别；自动识别与厂商选项互斥，H3C 和 Huawei 可以同时勾选。取消全部厂商后恢复自动识别。只保存厂商键，不保存补全过程或输入内容。

配置内容和临时编辑区均支持 Tab。唯一候选直接补全并推进到参数；多个候选先扩展共有前缀，再显示候选。Tab/Shift+Tab 或上下键切换，Enter 确认，Esc 关闭；继续输入会关闭旧候选。鼠标也可选取。补全替换当前词，保留缩进、其他行和光标后的内容，一次撤销恢复该次替换。只读预览不补全。

支持后续关键词、命令缩写、`undo`、可选组、选择组、重复组和参数后的关键词。参数占位只作提示；接口类型、当前文档中已声明的 VPN、策略等对象可以补全。对象复用依据确切参数类型和命令范围，QoS/流量策略名称不会被套用到 SSL、隧道等其他策略；不明确的参数保持提示。不会从密码、用户、安全字符串中提取候选，不生成地址或设备参数。

## 自动识别

识别扫描当前编辑区光标前后的配置，排除正在补全的行，按具有区分度的完整命令特征计分。重复同类特征只计一次。对象名提取也排除当前行，避免把正在输入的半个名称误认为已有对象并追加空格。

- Comware 示例：IRF、Bridge/Route-Aggregation、`port access vlan`、`stp global enable`、`lldp global enable`、`line vty` 和 Comware 版本头。
- VRP 示例：Eth-Trunk、`port default vlan`、`stelnet server enable`、特定堆叠/认证命令和 Huawei 软件版本头。
- `system-view`、`sysname`、`vlan`、普通接口、通用路由协议和注释中的厂商名称不能把范围锁定为单一厂商。
- 任一厂商有足够的特征即可保留该厂商。双方均有特征时保留双方；证据不足时回退到全部已支持厂商。长文档扫描全部内容，不以抽样遗漏混合厂商。
- 当前视图只影响候选排序，不删除其他视图的合法候选；未知型号和拼接片段不会因严格视图过滤而失去可用补全。

## 指令库及来源

两套补全数据分别保存在 `netconfiglint/commands/data/h3c.json` 和 `huawei.json`。共享的是中立语法引擎，不是另一厂商的命令数据。

| 厂商 | 去重后的语法形式 | 官方参考范围 |
| --- | ---: | --- |
| H3C | 9,722 | S6805/S6825/S6850/S9850 Comware 7 Release 6715-6W100 |
| Huawei | 28,464 | CloudEngine S8700 V600R024C10；S300/S500/S2700/S5700/S6700 V200R024C00；CloudEngine 9800/8800/6800/5800 V200R024C00 |

数量包括命令、撤销形式、不同参数形式和查询/维护命令，不等于独立命令数量。来源为 [H3C 官方参考](https://www.h3c.com/en/Support/Resource_Center/EN/Home/Public/00-Public/Technical_Documents/Reference_Guides/Command_References/H3C_S6805_S9850_CRs_Release_6715-18388/00/) 与 Huawei 官方文档 [S8700](https://support.huawei.com/enterprise/en/doc/EDOC1100459368)、[S5700 系列](https://support.huawei.com/enterprise/en/doc/EDOC1100410645)、[CloudEngine](https://support.huawei.com/enterprise/en/doc/EDOC1100420140)。每条语法保留来源和视图信息。

采集处理了 H3C 官方 CHM 中 6,334 个 HTML 文件和 Huawei 3,761 个参考章节，识别两代 HTML 格式、区分关键词与参数、排除格式区中的型号/视图说明、合并相同语法。原始手册、逐页哈希和采集记录保存在本地忽略目录，不随软件发布。

这覆盖上述参考的可提取语法，不是所有型号、软件版本和许可证功能的统一命令全集。参数补全不是设备语法校验，也不会把现有静态分析中的 UNKNOWN 自动变成通过。缺少某个设备版本的命令时应补充相应官方参考，而不是套用另一厂商。

## 厂商是否独立：只读检查结论

当前 H3C 和 Huawei 有各自的检测器、配置解析器、视图归并、运行信息解析、规则注册及原生命令处理。AST 回归检查整个厂商目录，不允许导入另一个厂商的实现。H3C 注册 47 个规则，Huawei 注册 51 个规则。

历史 v2.4 中存在 H3C 的 `rules/adapter.py`；当前 v2.5 基线已经删除该适配器，Comware 不再转译原文或调用 Huawei 规则对象。当前独立指运行时和厂商数据独立，不代表历史实现没有代码衍生或相似算法。

现有 `commands/catalog.py` 在一个文件中维护两套独立命令族定义，它们共享目录工具函数。核心的数据模型、预算、诊断结构和插件派发也是中立公共实现。这些共享不属于跨厂商复用语义数据库。

型号/版本能力资料的完备程度不同：Huawei 有 `profiles/catalog.json`，H3C 目前以通用 Comware 范围为主，没有同等规模的具体型号能力库。它没有借用 Huawei 型号库，但不能因此宣称两个厂商的型号覆盖同样完整。本次未重构现有厂商解析器、规则或型号资料；新增了两套独立补全库。

## 维护与验证

`scripts/import_completion_catalog.py` 是离线导入工具；其可选依赖在 `constraints/catalog.txt`，不是软件运行依赖。例如：

```sh
python scripts/import_completion_catalog.py --vendor huawei --input build/catalog-cache --download --output netconfiglint/commands/data/huawei.json --evidence build/catalog-import.json
python scripts/import_completion_catalog.py --vendor h3c --input build/h3c-manual --output netconfiglint/commands/data/h3c.json --evidence build/h3c-import.json
```

H3C 输入目录需要先从上述官方 CHM 提取。导入工具只输出功能语法和来源，不复制手册说明或真实设备配置。下载固定为官方 HTTPS 主机；XML 使用防实体扩展解析，章节大小有上限。

`scripts/completion_errata.json` 保留 26 条手册排版括号勘误的原语法、修订语法、来源和章节。修订依据同一命令的参数说明及相邻形式，不代表真实设备已验证。导入时区分斜体参数与选择/重复标记，并拒绝尚未审查的不配对括号或混入参数的语法操作符。重新导入逐项比对规范化前的命令，没有丢失条目；相同语法合并后得到上述数量。回归检查完整库结构及 OSPF 日志、RA Guard、Sender ID 的实际后续关键词，防止只补出第一个词而丢失后续分支。

新增回归覆盖共有语法、重复证据、混合厂商、光标后的证据、大文档、手动覆盖、多选去重、参数组、接口类型、对象名、Unicode/UTF-16 光标、缩进、词中替换、取消、候选失效、只读、撤销和两个真实 QML 编辑器。打包冒烟还验证两个编辑区的四个补全案例及实际加载的库数量，避免仅源码测试成功而漏带 JSON。

Windows 本地常规套件 796 项通过，覆盖率 90.41%，独立性能用例通过。Debian 13 数据库修订后的常规套件基线 794 项通过（随后新增的两个策略对象隔离用例已在 Windows 验证），性能用例通过；真实 XCB 桌面两个编辑区的 9 项交互测试及应用冒烟通过。桌面验证发现并修复了候选列表高度归零的问题，鼠标选取同时检查候选在窗口内且有实际可见高度。

发布审计逐项比对两套 JSON 与源码，缺失或改变补全库会阻止上传。三端平台构建及公开便携包验收按对应实际运行记录确认。macOS 使用源码和托管 CI 验证，没有本地 Mac 硬件验收。Windows 便携包未做 Authenticode 签名。
