# v2.1 change scope and verification boundaries

The desktop offers four visible modes: configuration snippet, message, view-only, and full
configuration. The CLI continues accepting `snapshot` for existing scripts. The default remains
snippet. Full mode separates pasted `display` output from configuration lines, parses available
operational tables, and interprets matching log lines. View mode uses only observed operational
evidence and does not assert that missing configuration is a defect.

Message mode recognizes bounded IRF/MAD, BGP, OSPF, LACP, STP, link, address-conflict, device
resource, hardware, command-error, and authentication events. Its causes are investigative
hypotheses. Unclassified lines remain visible as needs-attention diagnostics, with source line
numbers. The Huawei CLI error forms are described in the official
[Huawei command error guide](https://info.support.huawei.com/hedex/api/pages/EDOC1100277644/AEM10221/04/resources/software/nev8r10_vrpv8r16/user/galaxy/vrp_cli_cfg_0008.html).

The view analyzer currently extracts Huawei routing/BGP/interface tables and LLDP brief rows, and
H3C diagnostic or prompt-style display sections for device/environment, link aggregation, M-LAG,
OSPF, IPv4 route counts, LLDP, optics, and log-buffer overwrite evidence. LLDP edges use the
documented [Huawei brief](https://info.support.huawei.com/hedex/api/pages/EDOC1100277650/AZM1016J/04/resources/command/yunshan/LLDPDISPLAYNEIBRIEF%28LLDPOM%29.html)
and [H3C list](https://www.h3c.com/en/d_202603/2792651_294551_0.htm) layouts.

The H3C IRF check recognizes common IRF commands and flags a two-member sample where both
member ports use the same side. It reports this as inferred because the text cannot prove the
physical cable path. The official [H3C IRF guide](https://www.h3c.com/en/d_201906/1192536_294551_0.htm)
requires directly connected peers to use different IRF port indices.

History is enabled by default and now stores complete source and diagnostic objects locally.
Opening a record restores the earlier workspace. Reanalysis without changes does not append a
record; changing source/mode/vendor creates a new record. Closing history through Settings
requires confirmation and deletes the saved file. The portable ZIP places application-owned
history, settings, QML cache and temporary files under its extracted directory. Operating
system audit logs, file-access traces, crash reporting, and antivirus records are outside the
application's control and are not covered by the delete-folder property.

The command database is intentionally bounded. Recognized syntax does not imply every command
is semantically checked for every Huawei/H3C model, card, license, and release. Unmodeled H3C
commands remain source-preserved with UNKNOWN diagnostics. Supported source fixtures and hosted
platform tests provide reproducible evidence, but only matching devices and software releases
can establish real command acceptance and runtime behavior.
