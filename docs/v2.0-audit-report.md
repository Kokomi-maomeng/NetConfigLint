# NetConfigLint v2.0 审计与样本验收报告

本报告区分“已复现”“测试覆盖”“静态风险”和“仍需现场确认”。两个用户提供的文件仅用于本机分析，没有改写，也不随公开仓库或安装包发布。下文只保留聚合结果，不包含生产地址、账号或配置原文。

## 范围与方法

- 阅读检测、解析、规则、覆盖率、导入、导出、历史、GUI、打包和卸载主路径；核对规则注册与实际调用、异常边界及未使用代码。以 Ruff、mypy、Bandit、依赖审计、Vulture 和回归测试辅助检查；这些工具不能证明“零漏洞”或所有代码都有业务价值。
- 对真实 H3C 预配置片段和设备诊断包分别作导入、识别、配置/运行状态分离、诊断、覆盖率、行号、预览、语法高亮及导出检查；用脱敏合成样本补充 GUI 交互和格式组合测试。
- 分别验证源码运行、编译后运行、Windows 安装/卸载、Debian 13 安装/卸载和托管 macOS 构建/运行。CI 的系统矩阵是兼容性抽样，不等于所有硬件、驱动、DPI 或企业策略均已现场通过。

## 发现、处理与验收边界

| 事项 | 结论与处理 | 后续验收条件 |
| --- | --- | --- |
| H3C 命令覆盖 | 47 个已注册 H3C 规则处理已建模语义；未建模配置逐行给出 UNKNOWN、来源行号和语义覆盖状态，不再用“处理完成”冒充“命令全部支持”。 | 对明确机型/版本补充官方命令参考与真机/实验室用例；UNKNOWN 不能在生产决策中当作通过。 |
| 运行输出误判 | 诊断包先选定当前配置，再解析硬件、邻居、聚合、路由、日志等快照；运行输出不参与配置规则覆盖率。 | 新增诊断包格式须测章节边界、重复 `display`、截断与异常编码。 |
| GUI 真可用性 | 文件导入、来源行跳转、诊断筛选、卡片重排、导出和高亮均有真实组件/控制器测试。大文件使用有界只读预览，避免把 23 万行直接交给 QML 编辑器。Windows 扩展客户区原生标题栏遮挡已修正。 | 仍需在更多 DPI/缩放、多显示器和显卡驱动上人工目测；高亮是已知词法/未支持行标记，不是任意 H3C 命令的智能语义识别。 |
| 异常与安全 | 导入有大小/行数界限、混合换行和异常字节提示；失败分析不会伪造已验证状态。静态安全与依赖扫描未发现阻断项，高置信度死代码扫描未发现可直接删除的遗留块。 | 这不构成零漏洞、零死代码证明；新依赖/解析规则必须继续过安全与回归门槛。 |
| Windows MSI | 先前 MSI 将 Windows 10/11 的 `VersionNT64=603` 误判为旧系统；而 `WindowsBuild` 在新系统也可能报告兼容值 9600，因此改为查询系统注册表实际构建号来限定 Windows 10+。另发现 `Common*Folder` 被错误解析到源盘根目录，已改回经实装验证的 `ProgramMenuFolder`/`DesktopFolder`，保留 HKLM 组件键路径。两轮测试覆盖自定义目录+保留数据、默认目录+删除数据。 | 发布构建必须通过独立 Windows runner 的两轮 MSI 验收；主机上的 Codex 虚拟化应用数据视图不能单独用作物理文件残留结论。 |
| 跨平台 | Windows 原生/软件后端与便携包、Debian 13 真机/VM 安装、macOS 托管构建/运行均有候选版证据。 | 不声称所有 CPU/GPU、系统补丁、企业安全软件兼容；macOS 无独立用户硬件安装验收。 |
| 发布信任 | Windows MSI 与 macOS PKG 没有可信签名/公证身份，文件名明确含 `unsigned`。 | 用户允许发布未签名版，但系统安全提示属预期；最终以标签、Release 工作流、下载文件和 SHA256SUMS 核对为准。 |

## 生产使用建议

1. 对拟上线设备先补齐**实际型号、Comware 构建号、板卡与许可**，核实 4 项平台依赖命令；对 Telnet、SNMPv2c 可写、旧 TLS 和 OSPF/VTY 风险做变更评审，而非一键套用诊断建议。
2. 对现网诊断的 DRCP 累计错误做两个以上时点的计数差分，并与链路事件关联；核对日志覆盖时段和采集完整性。当前单份导出不支持根因判定。
3. 在业务上把 `UNKNOWN`、证据缺失、快照不完整列为人工复核项；报告只是辅助审查，不替代设备配置校验、变更窗口和回退方案。

本报告的样本数值是当前两份文件的分析观察，不是对其他 H3C 系列、所有 Comware 发行版或实际转发结果的保证。发布是否合格还取决于对应提交的 CI 与 Release 验收结果。
